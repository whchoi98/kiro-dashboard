# Deploy & CDK Guide — kiro-dashboard

Request: $ARGUMENTS

**Authority**: `docs/runbooks/production-deploy.md` holds the full trap list
(Traps 1–8). This skill is the executable fast path; if they disagree, the
runbook wins and this file must be corrected.

## Stacks

`infra/bin/app.ts` instantiates 4 core stacks plus 1 opt-in:

```
KiroDashboardNetwork → KiroDashboardSecurity → KiroDashboardEcs → KiroDashboardCdn
                                    KiroDashboardCatalog (opt-in)
```

| Stack | Resources |
|-------|-----------|
| `KiroDashboardNetwork` | VPC (new, or existing via `EXISTING_VPC_ID`), NAT, SSM endpoints |
| `KiroDashboardSecurity` | ALB/ECS security groups, Cognito user pool, edge auth client |
| `KiroDashboardEcs` | Fargate service (ARM64), ALB, ECR, IAM task role (incl. `InfraReadOnly`), auto scaling 1–4 |
| `KiroDashboardCdn` | CloudFront + Lambda@Edge auth + SSM edge config |
| `KiroDashboardCatalog` | Only when `ATHENA_DATA_BUCKET_NAME` is set: Glue DB, `user_report` (11 fixed cols), legacy `by_user_analytic` (46 cols) |

**Region trap**: this box exports `AWS_REGION=us-east-1`. Pass
`--region ap-northeast-2` on every `aws` call; for CDK, export
`AWS_REGION`/`AWS_DEFAULT_REGION=ap-northeast-2` *after* sourcing `.env.deploy` —
CDK derives its region from the credential chain, so a stale `AWS_REGION`
silently overrides `CDK_DEFAULT_REGION` (runbook Trap 5).

## Step 0 — preflight (both paths)

```bash
npx jest        # the real gate — npm run lint is BROKEN (no ESLint config)
npm run build   # type check + production build
git status      # must be clean; never deploy a tree you cannot name by commit
```

## Step 1 — Path A or Path B

Decide from `cdk diff`, never from the changed-file list. Two deltas never
justify a CDK deploy on their own:

1. `X-Custom-Secret` — regenerated by `crypto.randomUUID()` on every synth, so it
   differs in **every** diff.
2. EdgeLambda `Code.S3Key` hash + new Version — appears whenever anything under
   `infra/lambda/edge-auth/` changed, including doc-only edits.

- No `infra/` change since the last deploy → **Path A**, skip `cdk diff`
- `infra/` touched → run `cdk diff`; Network + Security "no differences" and only
  the two phantom deltas above → **Path A**. Anything else → **Path B**

## Path A — image only (app code, docs, tests)

```bash
docker build -t kiro-dashboard .

ECR=120443221648.dkr.ecr.ap-northeast-2.amazonaws.com
aws ecr get-login-password --region ap-northeast-2 \
  | docker login --username AWS --password-stdin "$ECR"

SHA=$(git rev-parse --short HEAD)
docker tag kiro-dashboard:latest "$ECR/kiro-dashboard:latest"
docker tag kiro-dashboard:latest "$ECR/kiro-dashboard:$SHA"
docker push "$ECR/kiro-dashboard:latest"
docker push "$ECR/kiro-dashboard:$SHA"
# On a version release also tag X.Y.Z — see /release-guide.

SERVICE=$(aws ecs list-services --cluster kiro-dashboard-cluster \
  --region ap-northeast-2 --query 'serviceArns[0]' --output text)
aws ecs update-service --cluster kiro-dashboard-cluster --service "$SERVICE" \
  --force-new-deployment --region ap-northeast-2
aws ecs wait services-stable --cluster kiro-dashboard-cluster \
  --services "$SERVICE" --region ap-northeast-2
```

## Path B — CDK (IAM, env vars, stack changes)

Push a fresh image first if app code also changed.

```bash
set -a; source .env.deploy; set +a     # Trap 1: EXISTING_VPC_ID is mandatory
export AWS_REGION=ap-northeast-2 AWS_DEFAULT_REGION=ap-northeast-2  # Trap 5
cd infra && npx cdk diff               # Network/Security MUST be "no differences"
npx cdk deploy --all                   # Trap 2: Ecs + Cdn in ONE command (one synth)
```

- Deploying `KiroDashboardEcs` alone answers every request with 403 until Cdn
  catches up (secret mismatch).
- Missing `CUSTOM_DOMAIN` / `CUSTOM_DOMAIN_CERT_ARN` drops the alias and
  re-breaks the domain with `redirect_mismatch` — both live in `.env.deploy`.
- EdgeLambda old-version `DELETE_FAILED` ("replicated function") is benign.
- A new VPC in the diff means `EXISTING_VPC_ID` is unset: stop, do not deploy.

## Step 2 — verify (never skip)

```bash
# 1. running task uses the digest you pushed and is HEALTHY
TASK=$(aws ecs list-tasks --cluster kiro-dashboard-cluster \
  --region ap-northeast-2 --query 'taskArns[0]' --output text)
aws ecs describe-tasks --cluster kiro-dashboard-cluster --tasks "$TASK" \
  --region ap-northeast-2 \
  --query 'tasks[0].{health:healthStatus,image:containers[0].imageDigest}'

# 2. health endpoint 200 through the ALB (CloudFront always 302s pre-auth)
SECRET=$(aws cloudfront get-distribution-config --id EYIGNKS7E8VUM \
  --query "DistributionConfig.Origins.Items[0].CustomHeaders.Items[?HeaderName=='X-Custom-Secret'].HeaderValue | [0]" \
  --output text)
curl -s -o /dev/null -w '%{http_code}\n' -H "X-Custom-Secret: $SECRET" \
  "http://kiro-dashboard-alb-1956720821.ap-northeast-2.elb.amazonaws.com/api/health"

# 3. edge auth chain intact (302 to Cognito)
curl -s -o /dev/null -w '%{http_code}\n' https://d1n3t9phsfh9bp.cloudfront.net/

# 4. feature assertion: fetch the page/API this deploy shipped and grep for a
#    string only the new build renders
```

Report digest, health status, and the feature assertion. A failed check is not a
successful deploy — roll back or investigate.

## Rollback

```bash
ECR=120443221648.dkr.ecr.ap-northeast-2.amazonaws.com
aws ecr get-login-password --region ap-northeast-2 \
  | docker login --username AWS --password-stdin "$ECR"
docker pull "$ECR/kiro-dashboard:<prev-tag>"      # per-version or per-sha tag
docker tag  "$ECR/kiro-dashboard:<prev-tag>" "$ECR/kiro-dashboard:latest"
docker push "$ECR/kiro-dashboard:latest"
SERVICE=$(aws ecs list-services --cluster kiro-dashboard-cluster \
  --region ap-northeast-2 --query 'serviceArns[0]' --output text)
aws ecs update-service --cluster kiro-dashboard-cluster --service "$SERVICE" \
  --force-new-deployment --region ap-northeast-2
```

CDK deploys roll back by checking out the previous `infra/` revision and
redeploying `--all` (the secret rotates again, consistently).

## Troubleshooting

- **Health check failing** — `/api/health`, and `HOSTNAME=0.0.0.0` must be set for Next.js standalone
- **CloudFront 403 everywhere** — `X-Custom-Secret` mismatch between Cdn and Ecs: redeploy both in one command
- **Athena errors** — task role permissions and the `us-east-1` region, not `ap-northeast-2`
- **`/infra-cost` rows all `unknown`** — the image outran an IAM change: CDK-deploy Ecs+Cdn, then redeploy the image (runbook Trap 8)
